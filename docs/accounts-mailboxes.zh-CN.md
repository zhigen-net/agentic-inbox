# 独立账号与多域名邮箱

## 核心模型

一个登录账号可以访问多个邮箱。创建邮箱时输入名称和前缀，多选域名，即生成同前缀的多个地址：例如 `sales@site1.com` 和 `sales@site1.net` 共用一个邮箱、一套文件夹、草稿和授权。

每个邮箱有稳定标识。为兼容已部署的数据，API 的 `id` 沿用不可变的存储键，同时提供独立 `stableId`；默认展示/发件地址可以更换，DO 名和 R2 设置对象键不会随之变化。现有地址一旦登记，即使停用也保留占用权，不能被其他用户重新注册。

不同域名之间没有强制组关系。新增域名不会改变旧邮箱；管理员可以在某个邮箱下追加同前缀地址。第一版不开放不同前缀别名或邮箱自动合并。

## 已有管理员如何开始

1. 升级后继续通过原 Cloudflare Access 身份进入应用。
2. 打开首页 → **账号设置**，为自己的账号设置至少 12 位独立密码。
3. 确认密码登录可用后，再调整覆盖整个 Worker 的 Cloudflare Access 策略。
4. 如果需要让外部用户直接注册/登录，必须移除覆盖全站的 Access 门禁，或改成仅保护管理入口的路径策略。应用原生权限仍然保护邮件、管理 API、Agent 和 MCP。

**重要：** 代码部署不会自动删除你的 Cloudflare Access 应用或策略。保留它是为了避免管理员尚未设置密码时失去访问。若不调整外层策略，普通用户仍需先通过 Access，这不是原生登录失败。

应用只信任经过 issuer/audience/签名校验的 Access JWT；不信任客户端自行传来的邮箱头。原生会话优先于 Access 登录桥接。

## 全新安装，不使用 Access

- 配置 `ADMIN_EMAILS` 为管理员的真实登录邮箱。
- 在 Worker Secret 或构建 Secret 中设置至少 32 位随机 `BOOTSTRAP_TOKEN`。
- 首次访问 `/setup`，填写管理员邮箱、初始化凭据和自选密码。
- 任一管理员已有密码后，初始化入口自动拒绝再次使用。可删除不再需要的初始化 Secret。

密码通过 Web Crypto PBKDF2-SHA256 加盐保存。会话采用 Secure、HttpOnly、SameSite=Lax 的 Host Cookie；数据库只保存会话令牌摘要，默认 7 天过期。改密、重置、停用用户会撤销相关会话，并通过凭据版本防止旧登录并发恢复失效会话。

## 注册与用户管理

管理后台的注册方式：

- **邀请注册**：默认。管理员创建用户后复制一次性邀请链接，私下交给该用户，24 小时内设置密码。
- **注册后审核**：用户自行申请，审批前不能登录或获得邮箱权限。管理员应通过可信渠道核对申请人身份后批准。
- **关闭注册**：停止自主申请；管理员已创建账户的有效邀请仍可用于激活。

邀请不会发送邮件。链接中的令牌放在 URL fragment 中，不作为页面请求参数发送；服务端仅存摘要。管理员可生成 1 小时有效的密码重置链接；本版没有自动发送找回密码邮件。

用户管理支持启用、停用、审核、管理员角色、生成重置链接，以及：

- 是否允许自行创建邮箱。
- 可以选择哪些域名。
- 自建邮箱上限（默认 3）。管理员分配的邮箱不占用该用户自建额度。
- 每日发信尝试上限（默认 100）和 AI 操作上限（默认 50）。设为 0 即关闭，日额度按 UTC 日期统计。

管理员可在首页创建邮箱时指定所属用户，也可以在后台为现有邮箱添加 Editor / Viewer 成员。注册本身不授予邮箱、创建权限或域名权限。邮箱转让、授权和停用由管理员控制。

## 创建和管理邮箱

创建界面：邮箱名称、前缀、多选域名、默认地址；管理员另可指定用户。最多 20 个地址。

提交前后均校验权限和地址冲突。全部地址在同一 D1 事务中占用，一个冲突则整体不创建。配额在数据库触发器中再次校验，避免并发绕过。新邮箱未完成 R2/DO 初始化时会停用保留，管理员可检查后恢复。

用户在邮件管理界面左侧切换邮箱，列表带收件箱未读数。写信时选择该邮箱实际可用的发件地址；回复优先使用邮件保存的实际投递地址，不可用时回到默认/可用地址。草稿保存所选发件身份。

地址可以分别控制收信和发信，也可以整体停用。停用默认地址或关闭其发信前，必须先更换默认地址；历史邮件不删除。

共享邮箱成员共用邮件和状态，私人 AI 会话按用户与邮箱隔离。Viewer 不能通过 API、Agent 或 MCP 绕过只读限制。

## 域名管理

在后台新增域名，完成 Cloudflare Email Routing/DNS 和 Email Service 发信验证，再启用收信/发信。数据库保存域名状态，日常添加域名不再要求修改 `DOMAINS` 后重新部署。

后台 MX 检测只判断是否存在指向 Cloudflare 的 MX 记录，不会声称发信验证已经完成。收发开关由管理员确认后开启，实际投递仍受账户服务和 DNS 配置影响。

历史 `DOMAINS` 仅用于首次导入已有配置；历史 `EMAIL_ADDRESSES` 不再作为新邮箱创建的授权规则。新授权由用户域名权限和地址映射统一控制。

## AI 与发送额度

每日额度由数据库统一执行，API 和 MCP 共用用户的发送额度，交互 Agent 和需要 AI 校验的 MCP 工具受 AI 额度约束。额度按尝试/操作计数，发送失败也可能占用次数；供应商配额与原邮箱发送速率限制仍同时生效。

新邮箱默认关闭收信自动草稿。管理员可在邮箱设置开启：每邮箱每日最多 25 次，有所属用户时还会消耗其 AI 额度。旧邮箱未设置此开关时沿用原行为。额度耗尽不影响收信，邮件先落库，自动任务只记录跳过原因。

## 旧数据与回滚

迁移只增加表、列、索引和配额触发器，不删除、改名旧数据。旧邮箱自动补齐地址映射；管理员首次打开目录时会分页核对 R2 中的旧邮箱设置，补齐遗漏目录记录，但不重新启用已停用邮箱。

邮件继续存放在原 Mailbox DO，附件继续使用原 R2 对象键。新邮件保存实际信封收件地址。相同原始邮件投递到同一个邮箱的不同别名时按邮箱去重，不生成独立邮箱。

回滚仅回退代码，不回退数据库；回滚到独立账号之前的版本会重新要求 Access。回滚到团队权限之前的版本还可能恢复全邮箱访问，应先限制外层访问策略。不要清空 D1 或重建 DO/R2。

## 验收与测试

`npm test` 覆盖密码/会话、邀请/审核、一次性重置、初始化关闭、跨站请求、限流、域名授权、并发配额约束、地址冲突回滚、地址停用保留、别名投递、旧数据恢复、MCP 与 Agent 授权。workerd 测试运行真实生产 HTTP 认证中间件和 D1/DO，SSR 渲染模块仅在该测试中替换。

真实收发邮件、域名 DNS 和外层 Access 策略需在目标环境验收；自动测试不发送真实邮件或调用付费 AI。
