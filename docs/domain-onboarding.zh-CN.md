# 域名检查、配置与跨账户接入

## 第一次使用

1. 管理后台 → 域名管理 → 服务连接，添加域名所属 Cloudflare 账户 ID 与 API 令牌。一个账户可供多个域名使用。
2. 打开域名“检查与配置”，在接入设置中选择账户连接并保存。根域名自动查找 Zone；子域名可填父 Zone，但不会自动修改父域名的 Catch-all。
3. 查看完整状态检查，再到配置向导生成变更预览。确认后才会修改 Cloudflare 配置。
4. 运行收信和发信测试，最后确认系统的域名/收信/发信开关符合预期。

添加域名后自动打开向导；检测全部可逐一更新现有域名。注册商所在地不影响接入；DNS 托管、域名所属 Cloudflare 账户和注册商是独立概念。

## 状态如何理解

系统开关只决定应用是否允许使用域名，不代表配置完成。完整检查将 DNS、账户授权、服务配置、Catch-all、独立地址规则和实际收发记录分开显示。

- 已通过：仅表示该项检查通过。例如 MX 指向 Cloudflare，不代表路由到本站；服务接受发送，不代表对方收到。
- 待配置：已成功读取，确实缺少该项配置。
- 权限不足：服务返回 401/403，不能据此认定没有配置。
- 尚未验证：未授权、无法推断 DKIM 选择器，或没有实际收发记录。
- 需核对：已有其他邮件服务、地址规则或策略，需要人工确认。
- 检测/操作失败：超时、服务异常或最近发送失败，不会冒充待配置或正常。

报告保存检测时间，是时间点快照。DNS 变更后需要重新检查。收发历史从本次升级开始记录，旧历史缺失不意味着以前没有成功收发。正式邮件入库与统计写入独立，统计失败不会导致已成功的发送被误报重试。

## 服务连接与凭据

API 令牌以 AES-GCM 加密存入 D1，密钥为 Worker Secret `DOMAIN_CONFIG_KEY`；使用连接 ID 绑定密文上下文。列表、日志和检测报告不会返回令牌。可更新令牌；被域名引用时禁止删除连接。

正常部署自动生成缺失的随机加密密钥，并始终保留已有密钥。`--plan` 保持只读。不要删除或轮换这个 Secret，否则已有连接无法解密，需要重新输入令牌；备份应与 D1 一并规划。

Cloudflare 令牌仅授权所需账户和 Zone：检查需要 Zone 读取、Email Routing 规则/设置读取及 Email Sending 读取；自动配置另需 DNS 编辑、Email Routing 规则/设置编辑和 Email Sending 编辑。跨账户部署接入 Worker 另需对应账户 Workers Scripts 编辑。具体权限名称和 Email Sending 可用性以 Cloudflare 控制台为准。

部署令牌只用于构建，不会自动成为应用内服务连接。请在登录后的“服务连接”表单保存专用令牌，不要在聊天、URL、仓库或前端变量里提供令牌。

## 自动配置的边界

自动配置先检查现状并生成 10 分钟有效的计划；执行时重新检查，并拒绝过期、重复使用或配置发生变化的计划。

- 使用 Cloudflare API 返回的实际 DNS 要求，不编造 DKIM/SPF 值。
- 不替换其他服务的 MX，不覆盖冲突 SPF，不覆盖启用中的不同 Catch-all。
- 原有独立地址规则保持不变，可能优先于 Catch-all，需要管理员核对。
- 只自动配置已激活的独立 Zone 根域名。子域名使用手动向导，避免影响父域名邮件。
- 可明确勾选预览中的发信开通；需账户服务已可用，可能涉及服务用量计费。
- 不自动发布 DMARC 强制拒收策略，不修改网站 DNS。

外部 API 变更不能跨服务事务回滚。若中途失败，显示已完成项目，重新检测后生成新计划；不会通过删除已有 DNS 或路由来“回滚”。

## 跨 Cloudflare 账户

主系统部署时记录准确的 `INBOX_ACCOUNT_ID` 和 `INBOX_WORKER_NAME`。选择其他账户后，向导允许在该账户部署固定名称的域名接入 Worker；同名 Worker 如不带本站和域名的归属标记，拒绝覆盖。

切换收信连接或接入模式会撤销旧接入密钥，需重新部署接入 Worker 或更新适配器配置。变更前的收发记录会保留，但不会作为新接入配置已验证的证明。

接入 Worker 只包含该域名的 HMAC 密钥与主站地址，不包含账户 API 令牌。Email Routing 在域名所属账户将邮件交给此 Worker，再经 `/ingress/email/<domain>` 汇入主站。接口验证时间窗、域名、信封收件人、原始 MIME 哈希和签名；重复请求与重复 MIME 都会去重。失败返回失败状态，由上游按投递策略处理；目前没有额外的持久队列，因此需监控接入 Worker 与主站可用性。

如果主站仍有覆盖全站的 Access 门禁，必须为机器接入路径单独配置适当策略。签名接口不能绕过管理 API 或邮箱授权；不要为此开放其他私有路径。

发信可以选择域名所属账户的 Cloudflare Email Sending REST API，无需把域名迁到主账户。未指定独立发信连接的同账户域名与既有域名继续沿用原 `EMAIL` binding，避免仅添加 DNS 检查授权就改变原有发信路径；跨账户默认使用该账户 API。

## 外部 DNS 与其他邮件服务

保持外部 DNS 时，Cloudflare Email Routing 的 DNS 要求仍受平台限制。不要仅手动添加 Cloudflare MX 后就视为接入完成。

本版提供外部收信的签名原始 MIME 接口，以及可下载的协议、私密接入参数和 Cloudflare 接入 Worker 源码。第三方收信服务需支持该协议或部署适配器；不包含通用 SMTP 服务器、IMAP 拉取器或所有服务商原生 webhook 适配器。

签名协议：

```
HMAC-SHA256(secret,
  timestamp + "\n" + requestId + "\n" + envelopeFrom + "\n" + envelopeTo + "\n" + rawMimeSha256Hex)
```

其中最后一项实际为原始 MIME 的 SHA256 小写十六进制字符串（不是再哈希一次该十六进制字符串）。请求正文为原始 MIME；HTTP 头为 `X-Inbox-Time`（Unix 秒）、`X-Inbox-Id`（UUID）、`X-Inbox-From`、`X-Inbox-To`、`X-Inbox-Signature`（小写十六进制）。时间偏差最多 5 分钟，正文最大 25 MiB。空信封发件人允许用于退信。保持原信封收件人，不能用 To/Cc 头代替。

外部 DNS 发信可选择独立 Resend 连接，在 Resend 登记域名后，向导可读取其验证状态及所需记录。DNS 仍需按服务商给出的实际值配置。Resend 收信 webhook 需要按上述协议适配，不能直接把事件 JSON 投递到原始 MIME 接口。

## 实际收发测试

收信：生成 30 分钟有效的随机测试地址，从管理员控制的外部邮箱发送，再手动检查到达结果。测试邮件不会写入正式邮箱，也不会消耗自动草稿额度。它证明链路到达，正式地址入库另行验证。

发信：选择此域名下已创建且允许发信的地址，填写管理员控制的外部收件邮箱，确认后发送真实测试邮件。每域名每小时最多 5 次，并计入用户发信额度。服务接受后仍需在对方收件箱确认，并检查 SPF/DKIM/DMARC 和垃圾邮件情况。系统不会自动给用户发送测试信。

## 验证范围

自动测试使用模拟服务 API 验证权限、冲突阻断、过期/单次计划、配置漂移、凭据加密、跨账户部署归属校验、签名防篡改和重复投递，并在真实 workerd 中验证无需登录的签名接入路径仍需要有效签名。

测试不修改真实域名 DNS、部署用户账户接入 Worker 或发送真实邮件。各账户实际服务权限、平台套餐和 DNS 生效情况，需要通过向导的检查与管理员主动测试验收。
